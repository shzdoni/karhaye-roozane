# 📱 کارهای روزانه — راهنمای کامل

برنامه‌ی فارسی و راست‌به‌چپ مدیریت کارها، عادت‌ها، گربه‌ی مجازی و چالش‌های دوستانه.

- نسخه‌ی آنلاین: <https://shzdoni.github.io/karhaye-roozane/>
- مخزن: <https://github.com/shzdoni/karhaye-roozane>
- نسخه‌ی فعلی: **۳.۴.۴**

> برنامه **local-first** است: داده‌ها اول روی همان دستگاه ذخیره می‌شوند و بدون اینترنت کار می‌کند.
> بخش‌های ابری (رتبه‌بندی، فید، چالش، پشتیبان رمزدار) اختیاری‌اند و فقط بعد از ورود با ایمیل/گوگل و با اجازه‌ی خودت فعال می‌شوند.

## ✅ نصب روی گوشی

### آیفون / آیپد
1. لینک را در **Safari** باز کن (نه داخل تلگرام).
2. **Share** ⤴️ → **Add to Home Screen** → **Add**.

### اندروید
1. لینک را در **Chrome** باز کن.
2. منوی ⋮ → **Add to Home screen** / **نصب برنامه**.
3. برای اعلان‌ها دکمه‌ی «🔔 اجازه‌ی اعلان» را بزن.

### ویندوز / مک / لینوکس
- در Chrome/Edge دکمه‌ی نصب در نوار آدرس ظاهر می‌شود، یا از منو **Install** را بزن.

> ⚠️ «Clear Website Data» مرورگر داده‌ی محلی را پاک می‌کند. هر چند وقت یک بار پشتیبان فایل یا پشتیبان ابری رمزدار بگیر.

## 🔐 امنیت و حریم خصوصی

### داده‌ی محلی
- کلید `localStorage`: `dailyTasksApp_v1` (نسخه‌ی schema: ۲).
- «قفل با رمز» کل وضعیت را با **AES-GCM** و کلید مشتق‌شده با **PBKDF2 (۱۵۰٬۰۰۰ دور)** رمز می‌کند؛ رمز ذخیره نمی‌شود.
- پشتیبان JSON شامل کارها، تاریخچه، XP/سکه، گربه (مرحله/آمار/اسم/اسباب‌بازی/سابقه‌ی مراقبت)، نشان‌ها و تنظیمات است.

### سمت سرور
- در `index.html` فقط **کلید عمومی** وب Firebase هست؛ هیچ Secret، Service Account یا Admin SDK در مخزن و کلاینت نیست.
- احراز هویت: مهمان (ناشناس)، ایمیل/رمز، Google.
- **هیچ مجموعه‌ای عمومی خواندنی/نوشتنی نیست.** قوانین در `firebase-rules/` هستند.

### خلاصه‌ی قوانین Firestore
| مسیر | اجازه |
|---|---|
| `users/{uid}` | فقط صاحب سند؛ XP هر آپدیت حداکثر +۱۰۰، روز حداکثر ۳۰۰، هفته حداکثر ۵۰۰؛ `invite`/`created` تغییرناپذیر؛ `blocked`/`blockedNames` حداکثر ۲۰۰ کلید |
| `publicProfiles/{uid}` | خواندن برای واردشده‌ها، نوشتن فقط صاحب با اجازه‌ی `share=true` و کلیدهای حریم خصوصی معتبر |
| `friendships/{uid}` | فقط صاحب؛ حداکثر ۵۰۰ لینک |
| `invites/{code}` | ساخت فقط با `uid` خودت و کد ۶ کاراکتری؛ `exp` اختیاری تا ۴۰ روز (نسخه‌های قبلی بدون exp هم مجازند) |
| `feed/{owner}/posts` | خواندن فقط صاحب یا دوست دوطرفه با `share/feed=true` و **بدون بلاک دوطرفه**؛ ساخت فقط صاحب؛ واکنش فقط کلید خودت و فقط 💪❤️🔥🎉؛ حذف فقط صاحب |
| `rooms/{id}` | خواندن/نوشتن **فقط میزبان و مهمان**؛ پیوستن با update اتمی `g`؛ هرکس فقط امتیاز خودش؛ `exp` اجباری و حداکثر ۸ روز؛ اتاق منقضی برای همه (جز حذف میزبان) بسته است |
| `backups/{uid}` | فقط صاحب؛ blob ≤ ۹۰۰٬۰۰۰ کاراکتر |
| `sync/{uid}` | همگام‌سازی رمزدار: فقط صاحب؛ blob ≤ ۹۰۰٬۰۰۰، `rev` عدد ≥۱، `dv` متن؛ خواندن فهرست ممنوع |
| `reports/{id}` | ساخت فقط با `by` خودت و شکل دقیق؛ خواندن/حذف فقط گزارش‌دهنده؛ ویرایش ممنوع |
| `pointTransactions/ achievements/ pets/ challenges` | کلاینت فقط می‌خواند (برای آینده‌ی Functions)؛ نوشتن ممنوع |

### امتیاز و ضدتقلب — وضعیت واقعی
| لایه | اکنون (بدون Blaze) | بعد از استقرار Functions |
|---|---|---|
| ذخیره‌ی XP/سکه | محلی + sync در `users` با سقف قوانین | فقط سرور (`awardPoints`) |
| سقف روز/هفته | قوانین: روز ≤۳۰۰، هفته ≤۵۰۰، هر آپدیت +۱۰۰ | سرور با ساعت UTC و سقف مشترک |
| تکرار پاداش | کلاینت جلوگیری می‌کند (قابل دور زدن) | شناسه‌ی یکتای تراکنش سمت سرور |
| زمان دستگاه | مؤثر نیست (فقط تاریخ محلی برای نمایش) | ساعت سرور معیار است |
| جدول رتبه | امتیاز اعلامی کلاینت (قابل تقلب آهسته) | امتیاز نوشته‌شده توسط سرور |

**صادقانه:** تا وقتی توابع مستقر نشده‌اند، «صحت کامل امتیاز» تضمین‌شده نیست. پس از استقرار، فایل `firebase-rules/firestore.rules.stage2` را منتشر کن تا نوشتن مستقیم `xp/coins` از مرورگر کامل بسته شود. کلاینت اگر با خطای دسترسی روبه‌رو شود، خودکار بدون `xp` می‌نویسد و از کار نمی‌افتد.

### همگام‌سازی رمزدار چنددستگاهی (آزمایشی)
- در تب باشگاه، «🔐 روشن کردن همگام‌سازی»: یک رمز (حداقل ۶ کاراکتر) می‌دهی؛ کلید PBKDF2/AES-GCM فقط روی همین دستگاه در **IndexedDB** ذخیره می‌شود و به سرور نمی‌رود.
- هر تغییر پس از ۱۵ ثانیه (در صورت تغییر واقعی) و حداکثر با `rev` اتمی در `sync/{uid}` آپلود می‌شود.
- دستگاه دوم با همان رمز وصل می‌شود؛ اگر نسخه ابری جدیدتر باشد و این دستگاه تغییری نداشته باشد، خودکار اعمال می‌شود. اگر هر دو تغییر کرده باشند، **تعارض** نشان داده می‌شود و خودت یکی را انتخاب می‌کنی؛ قبل از جایگزینی، یک نسخه محلی نگه داشته می‌شود.
- محدودیت: ادغام فیلد‌به‌فیلد انجام نمی‌شود (آخرین نسخه برنده است) و این قابلیت هنوز «آزمایشی» است.

### بلاک و گزارش
- دکمه‌ی 🚫 روی پست هر دوست: با تأیید، طرف بلاک می‌شود، از دوستان حذف می‌شود و فیدش (حتی با لینک مستقیم) با قوانین سرور قطع می‌شود. فهرست مسدودها زیر فید با دکمه‌ی «رفع مسدودی» می‌آید.
- دکمه‌ی ⚠️ گزارش با دلیل (۳ تا ۲۰۰ کاراکتر) در `reports` ثبت می‌شود؛ فقط برای بررسی نگه‌داری می‌شود.
- دکمه‌ی 🗑 روی پست خودت آن را حذف می‌کند.

### حریم خصوصی جدول رتبه‌بندی و فید
| کلید | پیش‌فرض |
|---|---|
| اشتراک پروفایل عمومی | خاموش |
| نام / امتیاز / نشان‌ها / گربه | روشن (بعد از اشتراک) |
| فعالیت در فید | روشن (بعد از اشتراک) |
| وضعیت آنلاین | **خاموش** |

- فید فقط از پست‌های خودت و دوستانی خوانده می‌شود که هر دو طرف رابطه را ثبت کرده‌اند، اشتراک فیدشان روشن است و بلاک نکرده‌اند.
- عنوان کارها، یادداشت‌ها و ژورنال‌ها هرگز به سرور نمی‌روند؛ پست‌های فید متن‌های عمومی مثل «نشان جدید گرفت» هستند.

### پشتیبان ابری رمزدار
- کل وضعیت با رمز خودت (حداقل ۶ کاراکتر) رمز و فقط `ENC1:salt|iv|ct` در `backups/{uid}` ذخیره می‌شود.
- کلید از رمز مشتق می‌شود و هرگز آپلود نمی‌شود؛ رمز فراموش‌شده قابل بازیابی نیست.
- سقف متن رمزشده ~۸۵۰KB (سقف سند ۱MB).
- در بازیابی می‌توانی «ادغام» یا «جایگزینی کامل» را انتخاب کنی؛ قبل از هر تغییر پیش‌نمایش داده می‌شود.

### حذف حساب
- پست‌های فید جدید و قدیم با صفحه‌بندی، `users`، `publicProfiles`، `friendships`، `invites`، `backups`، `sync`، گزارش‌های خودت و اتاق‌های چالش (میزبان: حذف، مهمان: آزادسازی) پاک می‌شوند، عضویت RTDB حذف و در پایان حساب Auth حذف می‌شود.
- اگر بخشی ناموفق باشد، پیام «X مورد ناموفق» می‌آید و حساب حذف نمی‌شود.
- **واکنش‌های تو روی پست دیگران** فقط با Admin SDK قابل حذف است؛ تا استقرار Functions باقی می‌مانند (در پست دوست، اسم تو در `re` می‌ماند). تابع `accountDelete` همین را با `collectionGroup` و صفحه‌بندی پاک می‌کند و پیشرفت را در `deletions/{uid}` نگه می‌دارد.

## 🔥 راه‌اندازی Firebase (یک‌بار)

پروژه: `karhaye-roozane`. برای پروژه‌ی شخصی، `CLOUD_CFG` در `index.html` را عوض کن.

### ۱) Authentication
Anonymous، Email/Password و Google را فعال کن.

### ۲) انتشار قوانین Firestore
فایل `firebase-rules/firestore.rules`:

**کنسول:** Firestore → Rules → محتوا را جای‌گذاری کن → **Publish**.

**CLI:**
```bash
firebase deploy --only firestore:rules --project karhaye-roozane
```

### ۳) انتشار قوانین Realtime Database
فایل `firebase-rules/database.rules.json` (اتاق لایو قدیمی):

```bash
firebase deploy --only database --project karhaye-roozane
```

یا کنسول → Realtime Database → Rules → Publish.

> ❗ هرگز `".read": true` / `".write": true` نگذار. RTDB برای احراز نیاز به `?auth=<idToken>` دارد (Bearer رد می‌شود).

### ۴) Cloud Functions (آماده‌ی استقرار — فعال نشده)
`functions/index.js` شامل:
- `awardPoints`: Callable؛ هزینه‌ی هر عملیات فقط سمت سرور (`taskDone/fullDay/gameWin/riddleSolved/catCare/missionDone`)، شناسه‌ی یکتای تراکنش، تراکنش اتمیک، سقف روز ۳۰۰ و هفته ۵۰۰ با ساعت UTC، بدون احراز هویت اجرا نمی‌شود، تکرار پاداش نمی‌دهد و در خطا هیچ تغییری ثبت نمی‌شود.
- `accountDelete`: حذف آبشاری صفحه‌بندی‌شده (پست‌ها، واکنش‌های من روی پست دیگران، گزارش‌ها، اتاق‌ها، دعوت‌ها، پشتیبان/همگام‌سازی، `users/publicProfiles/friendships`) با ثبت پیشرفت در `deletions/{uid}`؛ Auth فقط در پایان و بعد از موفقیت حذف می‌شود.
- `expireRooms`: هر ساعت اتاق‌های منقضی و اتاق‌های قدیمی بدون `exp` را پاک می‌کند.

**هزینه و پیش‌نیاز (بدون تأیید مالک فعال نمی‌شود):** پلن Blaze لازم است. Blaze رایگان شروع می‌شود و فقط مصرف بالای سهمیه‌ی رایگان هزینه دارد: Functions ≈ ۲ میلیون فراخوانی رایگان در ماه، Firestore ≈ ۵۰ هزار خواندن/۲۰ هزار نوشتن روزانه، و Cloud Scheduler برای `expireRooms` ≈ یک اجرا در ساعت (در سهمیه‌ی رایگان). برای یک گروه دوستان معمولاً هزینه‌ی ماهانه صفر یا چند سنت است؛ برای اطمینان، Alert بودجه در Google Cloud تنظیم کن.

```bash
cd functions && npm install
firebase deploy --only functions --project karhaye-roozane
```
سپس اگر می‌خواهی نوشتن مستقیم XP از مرورگر کامل بسته شود:
```bash
# محتوای firebase-rules/firestore.rules.stage2 را در Firestore → Rules انتشار کن
firebase deploy --only firestore:rules --project karhaye-roozane
```
> قبل از stage2 مطمئن شو Functions کار می‌کند (یک `awardPoints` آزمایشی) و کلاینت نسخه‌ی ۳.۵.۰+ است. برای بازگشت: فایل `firebase-rules/firestore.rules` (مرحله ۱) را دوباره منتشر کن.
>
> ایندکس لازم: `collectionGroup("posts")` روی `re.<uid>` (کوئری نابرابری). اولین اجرای `accountDelete` ممکن است خطای ایندکس بدهد؛ لینک ساخت ایندکس در لاگ Functions می‌آید.

### ۵) App Check (آماده‌سازی شده — فعال نیست)
1. کنسول → App Check → اپ وب → **reCAPTCHA v3**؛ کلید سایت را بگیر.
2. توابع با `ENFORCE_APPCHECK=true` (متغیر محیطی) استقرار می‌یابند تا توکن الزامی شود. `awardPoints` و `accountDelete` این پرچم را می‌خوانند.
3. کلاینت نسخه‌ی ۳.۵.۰ هنوز توکن App Check نمی‌فرستد؛ **قبل از Enforce** باید `firebase-app-check-compat` و کلید سایت در `index.html` اضافه شود. تا آن زمان در کنسول فقط حالت **Monitoring** را روشن کن (بدون Enforce) یا فعلاً دست نزن.
4. بعد از دیدن درخواست‌های معتبر در Monitoring، Firestore و Functions را Enforce کن؛ سپس نسخه‌ی جدید کلاینت را آزمایش کن (ورود مهمان، فید، رتبه، چالش).

### ۶) GitHub Pages
Settings → Pages → Branch `main` / root. انتشار صفحه ۴۵–۶۰ ثانیه طول می‌کشد. Service Worker نسخه‌ی جدید را network-first می‌گیرد و نوار «نسخه‌ی جدید» را نشان می‌دهد.
